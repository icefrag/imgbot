# 01 · Brotato 开加速后波次秒表冻结

Status: ready-for-agent
Category: bug
Reported: 2026-11-04 (用户实测反馈)

## 现象

工具设定档位加速后,进入波次(游戏开始),倒计时秒表完全不动。

## 已确立的事实(triage 取证)

- Brotato 当前版本(2026-11-03 更新)已从 GameMaker 迁移到 **Godot 3.7.dev**
  (`Brotato.exe` + `Brotato.pck`,自解析 PE 得证)。
- Brotato.exe 静态导入的钟源面(KERNEL32):
  - 已钩: GetTickCount / GetTickCount64 / QueryPerformanceCounter(命中 188 槽,注入实测)
  - **未钩**: GetSystemTimeAsFileTime / GetSystemTime / GetLocalTime(墙钟族)
- Godot 引擎主循环/delta 走 QPC(=会加速);脚本侧 Time.get_unix_time_from_system() /
  OS.get_unix_time() 走墙钟(=1x 真速)。

## 用户判别性问答(2026-11-04)

- 除秒表外游戏本体(怪/子弹/动画):**也卡住/没变快** → 推翻混合钟源假设
- 秒表: **不动且波次永不结束** → 时间依赖逻辑真正停摆,非显示问题
- 档位: **1.5x/2x 低速档即复现** → 排除 Godot 物理步饱和(max_physics_steps)
- **恢复 1.0x 后仍不正常** → 加速窗口期间游戏进程内状态被持久损坏,
  卸钩不能自愈(需重启游戏进程)

## 当前假设(待复现细化)

非速率问题,而是加速期间某次时间读数(负 delta / 巨大跳变 / 冻结值)毒化了
Godot 3.7.dev(定制 fork)主循环的帧调度锚点,之后 step 恒为 0 或调度死锁;
嫌疑面: ①换档/扎基准瞬间的 fake 值不连续(seqlock 失败透真值恰逢锚点采样);
②188 槽包含显卡驱动/NVIDIA GL 栈等非游戏模块,其内部 swap timing 被缩放后
呈现异常;③Godot fork 的钟源非 QPC 直读(如 steady_clock 经 CRT 或双路径)。

## 复现计划(agent 自主)

1. 启动 Brotato(主菜单即可,无需进波次),PrintWindow 抓帧测菜单动画活性。
2. 绑定 + 设 1.5x,连续抓帧 15s 对比活性;设 0 恢复后再抓。
3. VEH crash 字段核对;必要时 bisect(只钩 QPC / 排除驱动模块)。
